## 1. What is being built, in one paragraph

`vc-knowledge` becomes the single knowledge base for Virto Commerce, and `vc-kb` becomes a plugin
that reads it. The 1.2 MB of hand-written knowledge in `vc-mcp-testing-module/plugins/vc-fix/knowledge/`
is **leaving the plugin and the project** and migrates into the base in the base's own form. The base
is obtained from `https://github.com/VirtoCommerce/vc-knowledge.git` and is never carried inside a
plugin. The goal for the demo is decision §3.1 of the review: show that the accumulation loop works,
not that anything got faster.

## 3. The owner's decisions, all of them

Taken 2026-09-16 and 2026-09-17. Treat as given; reopen only with evidence.

1. `vc-fix/knowledge` leaves the plugin and the project; it migrates into `vc-knowledge`.
2. The base comes from the Virto repository, never from inside the plugin.
3. The plugin's own operating instructions (`execution/*`, `diagnostics/*`, `shared-instructions`,
   `browser-quirks`, `storefront-selectors`, `architecture/*`, `graphql-test-cases-runner`) **stay
   with the skills**. They are not knowledge about the platform.
4. **Migration first, then the demo** — stream B before stream A.
5. The base is connected by **`/project-init`**: find an existing checkout (`KB_BASE` or a sibling
   `vc-knowledge`), else `git clone --depth 1` into `<project>/.vc-knowledge`; record
   `knowledgeBase: { repo, path, ref }` in `project-profile.json`; readiness row in `verify-access`;
   `--check` adds the field to old profiles. The vc-kb SessionStart hook only pulls.
6. Virto's agents **push to `main`**; CI runs `kb validate` and rebuilds the generated indexes and
   catalogs. Pull requests only for migrations.
7. ECL's **generic chapters are not touched**. Its 182 `[OBSERVED]` rows and chapter 14 migrate.
8. **BL ids stay in the entry subject**, with `kb show BL-…` resolving by that id.
9. **The plugin copy is canonical** after the re-port; the lab keeps `measurements/` and the
   archives and imports the tool from the plugin.
10. Contract copies (`api/graphql-schema.md` and the pasted field tables) are **deleted**, not
    migrated: the derived plane is their right form and `kb check` byte-compares it.
11. **Nothing is imported as `confirmed`.**
12. The demo runs **without the live arrival hook**; the hook is cited as a replayed measurement.
13. The rehearsal is a rehearsal, not a sixth measured round; its numbers stay labelled.

## 4. What is done

**B1 — the `normative` plane exists.** Rules are a third written store, beside `captured/` and
`flows/`.

| | |
|---|---|
| new | `src/rules.mjs` (id grammar, domain key, catalog order), `test/rules.test.mjs` (13 tests) |
| changed | `src/planes.mjs` (`WRITTEN_STORES.normative` → `rules/`), `src/capture.mjs` (identity by rule id, `NORMATIVE_EXEMPT`, the unattested first row, the empty-store guard, `attestedOf` tightened), `src/coordinates.mjs` (rules in the coordinate index, `writtenNeighbours`), `src/validate.mjs` (the rules store's gate), `bin/kb.mjs` (`--rule`, `kb rules`, `kb show BL-…`, stat, reindex, usage) |
| verified | **282 tests pass** (269 before). The live corpus rebuilds **byte-identically**; `kb validate` on a clone is green — 590 derived, 100 captured, 3 flows, 0 rules, 39 notices, unchanged |

Three design decisions inside it, each argued at the point of code:

* **A transcribed rule does not vote.** Its first row is kept whole and marked `attested: false`
  with a `whyNot`, so a rule read off a page reads 0 parties. No import arrives one confirmation
  short of the licence to act unverified.
* **A rule answers no question and needs no scope.** Both exempt at the door and the gate; requiring
  either would make an importer invent 216 unobserved values.
* **An observation does not supersede a rule.** The door points at `kb dispute`; both sides stay.

One latent defect fixed on the way: `kb reindex` wrote an index and a catalog for an empty store,
and `kb validate` then failed on that verb's own output. Latent in the flow store since it shipped.

**Housekeeping done:** the 14 probe rows a previous review pass left in the live `demand.jsonl` are
discarded; the diff is in the session scratchpad. `vc-knowledge` is clean.

## 7. Hard rules, still true

* `kb ask`, `kb how` and `kb deliver` **write** to the demand loop. Probe against a copy with
  `--base`, and pass a drive-letter path.
* Never run anything against the deployment. Read-only scripts and archived logs only.
* Writing verbs fail silently on a base that is not a base — `capture` refuses without `kb.json` now,
  and that refusal is the reason.
* Working inside `vc-kb-lab`, every tool call runs the lab's own `PostToolUse` hooks: text that
  merely mentions a route injects register entries and writes to `MEASUREMENT/`. Archive
  `MEASUREMENT/` before any measured run.
* Pin the source, not the value. A number copied onto a page drifts from the script that made it.
